# Распиновка TZT RK-ZYNQ7020-F v1.1

Устройство: **xc7z020clg484-2**.

Задание требует не предполагать распиновку по названию платы. Ни один вывод в
этом документе не угадан. Для каждого указан источник, и каждый дополнительно
сверен с базой устройства.

## Как получены данные

### Источник 1: штатный проект производителя (авторитетный)

На плате поставляется factory image вместе с исходным проектом Vivado. Это самый
надёжный источник, потому что именно с этой прошивкой плата отгружается, то есть
распиновка в ней заведомо рабочая.

```
RK-ZYNQ7020-F/5. Factory Image/factory/vivado/image_7020/
├── image_7020.xpr                              → part = xc7z020clg484-2
├── image_7020.srcs/constrs_1/new/
│   ├── gengral.xdc      → CFGBVS VCCO, CONFIG_VOLTAGE 3.3
│   ├── other.xdc        → PL-клок, LED, кнопки, SPI-дисплей
│   ├── io_40pin.xdc     → 40-контактные разъёмы расширения
│   ├── hdmi.xdc, pl_eth.xdc, serial_port.xdc, fmc.xdc → прочая периферия
└── image_7020.srcs/sources_1/bd/design_1/design_1.bd
                                                → clk_in1 FREQ_HZ = 50000000
```

## Ключевые аппаратные факты и их следствия

### PL-осциллятор существует, и он 50 МГц

Это снимает главную неопределённость переноса. На многих платах Zynq PL
тактируется только от PS через `FCLK_CLK0`, и тогда автономная сборка невозможна.
Здесь есть свой осциллятор, поэтому:

- сборка `spi_zynq_top` работает без PS и без софта;
- **частота совпадает с Altera-референсом (50 МГц)**, поэтому все значения
  `CLK_DIV` из исходного проекта переносятся без пересчёта, а timing-результаты
  напрямую сравнимы с отчётом Quartus;
- W17 — **MRCC**, то есть clock-capable. Vivado сам вставит глобальный буфер;
  ручное инстанцирование `BUFG` не нужно и не выполнено.

### На плате уже есть SPI-дисплей

Найдено в `other.xdc`:

```
#LCD
SPI_0_0_sck_io  → V18
SPI_0_0_io0_io  → U19     (MOSI; MISO отсутствует)
SPI_0_0_ss_io   → AA13
LCD_DC  → W13    LCD_LED → Y13    LCD_RST → AA18
```

Это, по всей видимости, SPI TFT-панель (типовая обвязка DC/RST/BL). Соблазн
использовать её как цель проверки велик — тем более что исходный Altera-проект
тоже управлял дисплеем. **Отклонено в качестве основной цели**, по двум причинам:

1. **Нет MISO.** Производитель выводит только `io0`, что нормально для SPI-TFT.
   Без обратной линии вся приёмная половина контроллера — включая синхронизатор
   и единственный известный дефект A-3 — осталась бы непроверенной.
2. **Линия не свободна электрически.** К ней подключён реальный дисплей, который
   будет интерпретировать произвольные посылки.

Дисплей остаётся **вторичной** целью: он полезен, когда потребуется проверить
работу с настоящим slave-устройством и корректность CS/DC-последовательностей.
Для этого достаточно переназначить три вывода в XDC.

### Почему SPI выведен на 40-контактный разъём

Разъём даёт четыре действительно свободных вывода с настоящим MISO и открывает
самую ценную проверку, не требующую внешнего оборудования: **джампер MOSI → MISO
превращает контроллер в петлю обратной связи**, в которой принятое слово обязано
совпасть с переданным. Это проверяет весь тракт целиком — сдвиг, пад,
синхронизатор, момент сэмплирования, порядок бит — при помощи одного провода.

MOSI (W8, бит 1) и MISO (W11, бит 2) намеренно назначены на **физически
соседние** контакты разъёма, чтобы джампер был коротким и его нельзя было
поставить не туда. Процедура — шаг 8 в [bringup.md](bringup.md).

## Физическое положение SPI на разъёме J1

Нужно для установки джампера в шаге 8 [bring-up](bringup.md). Получено
сопоставлением имён цепей схемы с выводами FPGA: цепь `IOn` занимает контакты
J1 `2n+1` и `2n+2`.

| Сигнал | FPGA pin | Имя цепи | Контакт J1 |
|--------|----------|----------|------------|
| `spi_sclk` | V8 | `IO9_P` | 19 или 20 |
| `spi_mosi` | W8 | `IO9_N` | 19 или 20 (второй из пары) |
| `spi_miso` | W11 | `IO10_P` | 21 или 22 |
| `spi_cs_n[0]` | W10 | `IO10_N` | 21 или 22 (второй из пары) |

MOSI и MISO лежат в **соседних парах контактов**, поэтому джампер петли — очень
короткий. Точное распределение внутри пары (чётный или нечётный контакт) взято из
автопарсинга схемы и перед установкой джампера требует визуальной сверки. Номера
выводов FPGA при этом авторитетны: они из XDC производителя, и именно от них
зависит битстрим.

Побочное наблюдение: SCLK и MOSI попали на две половины одной дифференциальной
пары (`IO9_P` / `IO9_N`) — то есть клок идёт по сильно связанной трассе рядом с
данными. При 1 МГц это не имеет значения. Если частота будет подниматься к
потолку 8.33 МГц, дешёвая мера предосторожности — перенести SCLK в другую пару.

## Дополнительно установленные факты

| Факт | Значение | Источник |
|------|----------|----------|
| Полярность PL_LED1/LED2 | **Активный высокий** (подтверждено) | `system-user.dtsi`: `GPIO_ACTIVE_HIGH`; на схеме LED через 240 Ω |
| Полярность PL_KEY1/KEY2 | **Активный низкий** (подтверждено) | `system-user.dtsi`: `GPIO_ACTIVE_LOW` |
| Выделенная кнопка сброса PL | **Отсутствует** | Аппаратный сброс заведён на PS (MIO13). W18 — обычная пользовательская кнопка, и её использование как сброса PL повторяет практику штатных демо производителя |
| Цепь PL-клока | Осциллятор → цепь `PL_CLK` → **R121 (33 Ω)** → W17 | Схема v1.1 |
| Дисплей на плате | **ST7789V**, 1.47", 172×320, SPI до 32 МГц | `system-user.dtsi`: `compatible = "sitronix,st7789v"` |
| Параллельный RGB-дисплей | **Отсутствует** | Есть только SPI ST7789 и HDMI в PL |
| Level shifter на 40PIN | **Отсутствует**, прямое подключение к FPGA | Руководство §1.19 |
| Контакты J1 39–40 | `VCC_3V3` через 4.7 кΩ | Это питание разъёма, а не подтяжка сигналов |

Максимальная частота SPI дисплея (32 МГц) заметно выше нашего потолка 8.33 МГц,
поэтому при использовании ST7789 как цели проверки контроллер работает с большим
запасом.

## Что осталось неподтверждённым

| Пункт | Статус | Как закрыть |
|-------|--------|-------------|
| **VCCO банка 13 = 3.3 В** | **РИСК:** это значение **по умолчанию**, но оно переключается резисторами RA на 1.8 / 2.5 / 3.3 В | Проверить установленные RA по схеме. Если напряжение иное, все `IOSTANDARD` в секции банка 13 обязаны измениться вместе с ним |
| Точный контакт внутри дифпары J1 | **TBD** | Визуально сверить с `ZYNQ7020-F V1.1位号&尺寸图.pdf` перед установкой джампера |
| Номинал R145 (контакты J1 37–38) | **TBD** | В netlist номинал не указан. На SPI-выводы не влияет |
| Конфигурация PS (DDR, MIO, тактовые частоты) | **TBD** | Board file для платы в Vivado отсутствует. Для интеграции с PS взять preset из штатного `design_1.bd` |

Отдельно стоит отметить, что найденная неоднозначность с VCCO — единственный
пункт, способный привести к аппаратному повреждению: если банк 13 переведён на
1.8 В, а битстрим объявляет LVCMOS33, выходные буферы будут работать вне
допустимого режима.

Последний пункт важен для варианта с AXI: полноценный block design с PS требует
корректной конфигурации DDR и MIO, которую нельзя угадать. Штатный
`design_1.bd` производителя содержит рабочую конфигурацию и должен служить
отправной точкой.
